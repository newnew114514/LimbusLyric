No function was added or removed by RC11.

RC11 FIX 1 — PRESERVE QQ TRACK-SWITCH QUARANTINE
=================================================
MediaSessionSync.bind_track:
- preserves an already-active QQ _qq_track_switch_hold_until_mono across metadata binding;
- does not create a new hold by itself;
- does not affect KuGou or NetEase.

MediaSessionSync._merge_uia_position:
- during that active QQ switch hold, a trusted GSMTC fallback is NOT echoed into `chosen`
  when no valid current UIA sample exists;
- therefore auto-local remains public until the quarantine expires / the new clock catches up;
- ordinary provider switching with no active duration-mismatch hold is unchanged.

RC11 FIX 2 — DROP STALE QQ AUTO-LYRIC RESULT BY LIVE DURATION
=============================================================
ControlPanel._on_auto_lyric_result:
- applies only to source/player QQ音乐;
- requires both result duration and live transport duration to be >0;
- requires live transport status playing/paused;
- tolerance = max(4500ms, 2% of larger duration);
- a larger mismatch marks the network result stale and does not apply it.

Regression examples:
- 221000 vs 221626 => ACCEPT
- 242000 vs 242112 => ACCEPT
- stale 242000 vs current 248583 => REJECT

This is intentionally an auto-result guard only. Manual lyric search behavior is unchanged.
